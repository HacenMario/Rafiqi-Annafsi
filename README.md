## ✨ المزايا

| الميزة | التفاصيل |
|---|---|
| 🗓️ **حجز بتاريخ + مواعيد موحّدة** | المتضرر يختار التاريخ والموعد: من 09:00 إلى 20:00 كل ساعة، وقت الفطور 12:00–13:00 مستثنى، ومواعيد اليوم الفائتة معطّلة تلقائياً |
| ⏰ **تذكير قبل ساعة من الموعد** | إشعار داخل المنصة + إشعار فوري على الهاتف للطرفين قبل الجلسة بساعة — يعمل على Railway (مجدول كل دقيقة) وعلى Vercel (فحص كسول) دون تكرار |
| 🤖 **جلسة المتابعة تُنشأ تلقائياً** | عند جدولة الجلسة القادمة ينشئ الخادم الجلسة بتفاصيلها (نفس الطرفين والموضوع والنمط) بحالة «مقبولة» — يكفي أن يدخل الطرفان الغرفة في الموعد |
| 💬 **إشعار رسالة جديدة على الهاتف** | إذا وصلت رسالة نصية والطرف غير فاتح للغرفة يصله إشعار فوري (بدون محتوى الرسالة حفاظاً على السرية) — ولا يُرسل شيء إن كان حاضراً |
| 🟢 **حضور الغرفة يعمل في كل المنصات** | نبض REST كل 10 ثوانٍ يحدّث عبارة «بانتظار الأخصائي/المتضرر…» فور دخول أو خروج الطرف الآخر — حتى في وضع المزامنة بلا Socket.io، وعبارة الانتظار تتناسب مع نوع الحساب |
| 🚻 **جنس المتضرر** | يحدده عند التسجيل (ذكر / أنثى فقط) ويمكن تعديله من الإعدادات |
| 🏷️ **تخصصات مخصصة للأخصائي** | يضيف تخصصاته الخاصة عند التسجيل ويعديلها أو يحذفها من الإعدادات — وتظهر كاملة في بطاقات الدليل (بلا اختصار «+ن») |
| 🕐 **تنسيق تاريخ موحّد** | YYYY/MM/DD HH:MM:SS في كل المنصة وكل اللغات — استغناء كامل عن التواريخ المحلية وAM/PM |
| 🔤 **حجم خط قابل للتكبير/التصغير** | من الإعدادات: صغير / عادي / كبير / أكبر — يُطبّق على المنصة كاملة ويُحفظ في جهاز المستخدم (إمكانية وصول لكبار السن وضعاف البصر) |
| 👥 **دليل الأخصائيين** | صفحة عامة ببطاقات جميلة: الصورة الشخصية (بحجم واضح دون تشوه)، التخصصات كاملة، سنوات الخبرة، عدّاد الجلسات المكتملة (يُحسب مباشرة من القاعدة) — مع pagination وحجز مباشر وزر تجاوب لا يتراكب مع النص حتى بالفرنسية |
| 📸 **صورة شخصية للمختص** | اختيارية عند التسجيل وتظهر للمتضرر في الدليل واختيار المختص — تغييرها أو حذفها من الإعدادات في أي وقت |
| 💗 **صفحة شكر وعرفان** | متاحة لكل الحسابات إلى جانب الصفحات الأخرى: رموز صغيرة تطفو بهدوء في خلفية جميلة بعيداً عن النص — الأدمين يعدّل النص (بالغات الثلاث) ويغيّر نوع الرموز من تبويب مخصص |
| 📊 **تصدير البيانات (Excel)** | من لوحة الأدمين: المستخدمون / الجلسات / بلاغات الأزمة / الاقتراحات — ملفات CSV تُفتح مباشرة في Excel |
| 🔐 **فصل دخول الإدارة** | صفحة مستقلة تماماً (من الفوتر/القائمة) بعيداً عن بوابة المتضرر والأخصائي |
| 🧑‍💻 **بوابة مختص موحّدة** | تبويبان «حساب جديد / تسجيل الدخول» بنفس نمط بوابة المتضرر |
| 📈 **عدّاد المتضررين** | عدد المتضررين المسجلين يظهر بجانب عدد الأخصائيين الموثّقين في الصفحة الرئيسية |
| ✨ **نافذة «لحظة اطمئنان»** | عند كل ولوج: عبارة دعم نفسي عشوائية (دينية / اجتماعية / حِكم) بلغة المستخدم الأخيرة، تختفي تلقائياً بعد 10 ثوانٍ (قابلة للضبط في الكود) — والأدمين يضيف ويعطّل ويحذف من تبويب «العبارات» (65 عبارة مزرَعة تلقائياً) |
| 💬 **جلسات عبر واتساب** | محادثة نصية أو اتصال صوتي 📞 أو مرئي 🎥 — بضغطة زر واحدة، بدون تسجيلات أو أدوات خارجية |
| 👤 **حسابات دائمة للطرفين** | المتضرر يدخل باسم مستعار يكتبه بنفسه + كلمة مرور + عبارة استرجاع — سجل جلساته ومحادثاته يبقى محفوظاً |
| 🔔 **جرس إشعارات داخلي** | عدّاد غير المقروء + قائمة منسدلة + تعيين الكل كمقروء + مسح الكل + عرض 5 ثم «المزيد / إخفاء» |
| 📳 **إشعارات فورية محصّنة** | Web Push (VAPID) مترجمة حسب لغة كل مستخدم + إعادة اشتراك تلقائية عند التدوير (لا تتوقف بعد أول مرة) |
| 🔊 **أصوات واجهة** | نغمات خفيفة للأزرار والتنقّل ووصول الرسائل والإشعارات — قابلة للإيقاف من الإعدادات |
| 🇩🇿 **هيكل تحميل بعلم الجزائر** | skeleton عند كل تحميل أو تنقّل بين الصفحات |
| 📝 **الاقتراحات والبلاغات** | أي زائر يراسل فريق التطوير (اقتراح / مشكلة) — تصل مباشرة للوحة الإدارة |
| 🔒 **هوية محمية** | تسجيل باسم مستعار فقط — لا بريد إلكتروني ولا بيانات شخصية للمتضرر |
| 🌍 **ثلاث لغات** | العربية (RTL كامل) · Français · English — تبديل فوري من الواجهة |
| 🌗 **وضع فاتح / داكن** | محفوظ لكل مستخدم |
| 🔔 **إشعارات فورية** | Web Push (VAPID) مبنية داخل التطبيق + Service Worker |
| 📱 **PWA** | قابلة للتثبيت على الهاتف والحاسوب — شاشة مستقلة وأيقونة خاصة |
| 🚨 **بروتوكول الأزمة** | كشف آلي لعبارات الإيذاء الذاتي (عربي/فرنسي/إنجليزي) → تنبيه فوري + أرقام نجدة + سجل للإدارة |
| ✅ **توثيق بصورة الشهادة** | الأخصائي يرفع صورة شهادته بأي جهاز وأي حجم (ضغط تلقائي) والإدارة تتحقق منها بصرياً |
| 🛡️ **إدارة بكل الصلاحيات** | توثيق · حذف أي حساب · تعيين كلمات مرور · إنشاء حسابات مباشرة · الملاحظات · إحصائيات · سجل الأزمات |
| 🧭 **تجربة موجَّهة** | مسار من 4 خطوات للمتضرر: انطلاق → موضوع → اختيار الأخصائي → حجز الجلسة |

### 📱 كيف تعمل الجلسات عبر واتساب؟

1. المتضرر يحجز جلسة ويختار النمط: **نص** / **صوت** / **صوت وصورة**.
2. في غرفة الجلسة يظهر زر أخضر واحد: يفتح واتساب مباشرة على محادثة الأخصائي مع **رسالة تعريفية جاهزة** (الاسم المستعار، الموضوع، الموعد).
3. للنمط الصوتي: يضغط المتضرر زر الاتصال الصوتي 📞 أعلى المحادثة — وللمرئي: زر المكالمة المرئية 🎥.
4. **المحادثة النصية المدمجة تبقى متاحة** داخل المنصة (تعمل عبر Socket.io وتغذّي بروتوكول كشف الأزمة تلقائياً).

> رقم واتساب الأخصائي إلزامي عند تسجيله، ويُخزَّن بصيغة دولية أرقام فقط (مثال: `213555123456`).

## 🏗️ البنية التقنية

```
خادم موحّد واحد (server.js) — منفذ واحد:
├── Next.js 16 (React 19)  → الواجهة + REST API
├── Socket.io              → المحادثة النصية الفورية + الحضور + كشف الأزمة (/socket.io)
├── MongoDB (mongoose)     → قاعدة البيانات — محلية أو Atlas
└── web-push (VAPID)       → إشعارات فورية
```

### 🗄️ مجموعات قاعدة البيانات (Collections)

| المجموعة | المحتوى | أهم الحقول |
|---|---|---|
| `users` | المتضررون + الأخصائيون | `role` (VICTIM/COUNSELOR/ADMIN) · `pseudonym` · `email` · `passwordHash/Salt` · `recoveryHash/Salt` (عبارة الاسترجاع) · `wilaya` |
| `counselors` | ملفات الأخصائيين المهنية | `userId` · `fullName` · `whatsapp` · `specialties[]` · `languages[]` · `diplomaImage` (base64) · `verificationStatus` (PENDING/VERIFIED/REJECTED) · `available` |
| `sessions` | جلسات الدعم | `victimId` · `counselorId` · `topic` · `mode` (TEXT/VOICE/VIDEO) · `status` · `crisisFlag` · `followUpAt` · `treatmentEnded` |
| `messages` | رسائل المحادثة النصية (تبقى محفوظة لمسار العلاج) | `sessionId` · `senderRole` · `content` · `createdAt` |
| `notifications` | إشعارات جرس الموقع الداخلية | `userId` · `key` · `title` · `body` · `read` |
| `feedbacks` | اقتراحات التطوير وبلاغات المشاكل | `type` (suggestion/bug/other/contact) · `subject` · `message` · `contact` |
| `push_subscriptions` | اشتراكات الإشعارات | `userId` · `endpoint` · `p256dh` · `auth` |
| `crisis_logs` | سجل عبارات الأزمة | `sessionId` · `source` · `phrase` · `action` |

> **ملاحظة للإدارة اليدوية**: `specialties` و`languages` مصفوفات نصية مباشرة. قيم التخصصات الصالحة: `trauma`, `grief`, `anxietyDepression`, `children`, `burnout`.

**لا بيانات تجريبية ولا حسابات افتراضية**: قاعدة البيانات تبدأ فارغة تماماً — أنت من يُدخل بياناتك الحقيقية (انظر الأسفل).

## 💻 التشغيل المحلي

المتطلبات: **Node.js 20.9+** (موصى به: 22 LTS) و**MongoDB** (محلي أو Atlas).

```bash
# 1) اعده البيئة
cp .env.example .env
#   ثم اضبط في .env:
#   MONGODB_URI=mongodb://127.0.0.1:27017/rafiqi-nafsi   (أو رابط Atlas)
#   ADMIN_PASSCODE=كلمة-مرور-قوية-خاصة-بك

# 2) الاعتماديات + التشغيل
npm install
npm run dev        # → http://localhost:3000
```

للإنتاج:

```bash
npm run build
npm start          # → http://localhost:3000
```

### 👤 إدخال أخصائيين حقيقيين

**الطريقة 1 — سكربت تفاعلي (الأسرع):**

```bash
npm run db:add-counselor
# يسألك: الاسم، البريد، رقم واتساب، التخصصات، اللغات، الخبرة...
# ويطبع لك رمز الدخول فوراً لإرساله للأخصائي
# خيارات إضافية:
node scripts/add-counselor.js --list              # عرض الأخصائيين
node scripts/add-counselor.js --verify <email>    # توثيق أخصائي
node scripts/add-counselor.js --unverify <email>  # إلغاء توثيق
```

**الطريقة 2 — التسجيل الذاتي:** الأخصائي يفتح «انخراط كأخصائي» في المنصة → يملأ الاستمارة (كلمة مرور + عبارة استرجاع + رقم واتساب + **صورة الشهادة** بأي جهاز وأي حجم — تُضغط تلقائياً) → ثم توثّقه أنت من لوحة الإدارة بعد معاينة الصورة.

**الطريقة 3 — من لوحة الإدارة مباشرة:** تبويب «الحسابات» → «إنشاء حساب جديد» → أخصائي (مع توثيق فوري اختياري) أو متضرر.

> الأخصائي الموثّق فقط يظهر للمتضررين. المتضرر ينشئ حساباً دائماً: اسم مستعار يكتبه بنفسه + كلمة مرور + عبارة استرجاع — ويسجّل دخوله في كل زيارة ليجد جلساته ومحادثاته محفوظة.

### 🪟 ملاحظات Windows (PowerShell)

السكربتات متوافقة مع Windows وLinux معاً (بدون صيغ يونكس). مشاكل شائعة أثناء `npm install`:

**1) خطأ شبكة `ECONNRESET`** — انقطاع أثناء تنزيل الحزم من سجل npm:

```powershell
npm cache clean --force
npm config set fetch-retries 5
npm config set maxsockets 3
npm install
```

إن استمر الخطأ:
- جرّب شبكة أخرى (نقطة اتصال الهاتف مثلاً) أو عطّل VPN مؤقتاً.
- أو استخدم سجلاً بديلاً: `npm install --registry=https://registry.npmmirror.com`
  (أعده لاحقاً بـ `npm config delete registry`).
- إن كنت خلف بروكسي: `npm config set proxy http://127.0.0.1:PORT` و`npm config set https-proxy http://127.0.0.1:PORT`.

**2) تحذيرات `EPERM` / `cleanup Failed to remove`** — غير خطيرة: قفل ملفات من Windows Defender أو OneDrive أو محرر مفتوح. الحل الوقائي:
- أغلق VS Code وأي طرفية تستخدم مجلد المشروع، ثم أعد المحاولة.
- شغّل PowerShell **كمسؤول**.
- استثنِ مجلد المشروع من الفحص الحيّ في Windows Defender.
- تجنّب وضع المشروع داخل مجلد تتم مزامنته مع OneDrive (انقله مثلاً إلى `C:\projects\rafiqi-nafsi`).
- إذا تعذر حذف `node_modules` المتبقية من محاولة فاشلة: أعد تشغيل الجهاز ثم `Remove-Item -Recurse -Force node_modules`.

### 📲 إشعارات الهاتف — التفعيل وحل المشاكل (v2.3)

> **جديد في v2.10.0 — إصلاح نافذة الحجز + محادثة الإدارة + تمرين 4-4-6 الفعلي + 115 عبارة بست لغات:**
> - **إصلاح جوهري في نافذة الحجز:** كانت كل المواعيد تبدو «محجوزة» ولا يمكن التمييز بين المتاح والمعطّل.
>   الآن: تُعرض **ساعات جدول الأخصائي فقط** (وكل الساعات إن لم يحدد جدولاً)، **المتاح أخضر واضح**،
>   المحجوز مشطوب بشارة «محجوز»، وفائت اليوم مشطوب رمادياً — مع مفتاح مزدوج (أخضر = متاح / أحمر = محجوز).
> - **صفحة «التواصل مع الإدارة» للمختصين حصراً:** دردشة مباشرة وسرّية بين كل مختص والإدارة
>   (نفس منطق دردشة المتضرر: بث فوري + استقصاء + إشعارات للطرف الغائب) — الإدارة تردّ من
>   تبويب «رسائل المختصين» الجديد في لوحتها، وإشعار الرد يفتح صفحة المحادثة مباشرة (?admin-chat=1).
> - **تمرين التنفس 4-4-6 بالخطوات الفعلية:** عرض خطوات التطبيق الثلاث حرفياً (شهيق من الأنف يملأ البطن /
>   حبس دون توتر / زفير كنفخ شمعة) + اختيار المدة **3 أو 5 دقائق** (13/21 دورة كاملة) + إرشاد نصي
>   تحت كل طور + عدّاد الوقت المتبقي — كما نصّ التمرين (3 إلى 5 دقائق حتى تهدأ ضربات القلب).
> - **النبذة التعريفية كاملة** في دليل الأخصائيين (كانت مقصوصة بسطرين).
> - **صفحة الدعاء نقية:** أُزيل زر «آمين» وعبارة الأجر وزر «نسخ/مشاركة الرابط» — بقيت الجدارية والدعاء فقط.
> - **مكتبة العبارات 115 عبارة** (+50 جديدة بلا تكرار) **كلها بالست لغات**: العربية، الفرنسية، الإنجليزية،
>   التركية، الروسية، الصينية — وكل العبارات القديمة (65) أكملت ترجمتها للغات الثلاث الجديدة.
> - **الحساب بانتظار توثيق الحرائق يرى التنبيه داخل نافذة الحجز فوراً** (وليس بعد محاولة الحجز فقط).
> - إصلاح: اختيار أول موعد حر اليوم أصبح يتجاهل المواعيد المحجوزة من متضررين آخرين.

> **جديد في v2.9.0 — المحادثات بلا جلسة + فضاء الأخصائيين + لوحة قيادة + توثيق المتضررين + 6 لغات:**
> - **الرد بلا جلسة**: صندوق محادثات في لوحة الأخصائي — يرى رسائل المتضررين (قبل الجلسة) ويردّ عليها مباشرة.
> - **فضاء الأخصائيين**: دردشة جماعية خاصة بالمختصين فقط لتبادل الخبرات والتنسيق.
> - **إشعارات ذكية**: الضغط على إشعار «رسالة في غرفة الجلسة» يفتح الغرفة مباشرة، وإشعار المحادثة يفتحها مع المرسل — حتى من إشعار الهاتف عند إغلاق المنصة.
> - **جلسة واحدة/يوم**: تُحتسب الجلسات المكتملة أيضاً — القاعدة صارمة الآن فعلاً.
> - **الموعد المحجوز مسبقاً**: شارة واضحة «محجوز» داخل الزر نفسه في نافذة الحجز.
> - **زر واتساب واحد** في غرفة الجلسة (يفتح المحادثة مع الطرف الآخر حسب دورك) بدل ثلاثة أزرار.
> - **ترتيب جلساتي**: الغرفة المفتوحة أولاً ثم المقبولة ثم المعلقة ثم المبرمجة لاحقاً ثم الملغاة — بتفرقة واضحة بين كل نوع + زر رجوع داخل الغرفة.
> - **توثيق المتضررين من الحرائق**: إثبات إلزامي عند التسجيل (البلدية/التاريخ/الوصف) + تبويب مراجعة في الإدارة — الحجز مغلق حتى الموافقة (منع استغلال الجلسات المجانية).
> - **لوحة قيادة الإدارة**: كل الإحصائيات — مستخدمون، جلسات (اليوم/الأسبوع/الحالات)، رسم 14 يوماً، الجنس، الولايات، أعلى الأخصائيين انشغالاً، فائزو التحديات.
> - **الجنس مفعّل**: الأخصائي يرى جنس المتضرر قبل القبول، ويحدد من إعداداته الجنس الذي يقبل التعامل معه (يُطبَّق على الحجز والمطابقة والخادم معاً).

الإشعارات الفورية (Web Push) تعمل لكنها تحتاج **تفعيلاً يدوياً مرة واحدة في كل جهاز**، وشروطاً تقنية يفرضها المتصفح:

**خطوات التفعيل:**
1. افتح المنصة → سجّل دخولك → **الإعدادات** → فعّل مفتاح «تفعيل الإشعارات» ووافق على طلب المتصفح.
2. اضغط «إرسال إشعار تجريبي» — إن وصل الإشعار فكل شيء يعمل.

**إن لم تصل الإشعارات، تحقق من هذه القائمة بالترتيب:**

| **iPhone / iPad (iOS 16.4+)** | Safari لا يسمح بالإشعارات إلا إذا ثبّتّ التطبيق أولاً: مشاركة ← **«إضافة إلى الشاشة الرئيسية»** ← افتح التطبيق من الأيقونة ← فعّل الإشعارات من الإعدادات |
| أندرويد كروم | يجب أن يكون الموقع **HTTPS** أو `localhost` — المتصفحات ترفض Push على http عادي |
| منعت المتصفح الإشعارات | أيقونة القفل بجانب الرابط ← الإشعارات ← «السماح» ثم أعد التفعيل من الإعدادات |
| مفاتيح VAPID تغيّرت في `.env` | اشتراكات الأجهزة القديمة تصبح باطلة — عدّل المفاتيح ثم أعد تفعيل الإشعارات من كل جهاز. **لا تغيّر المفاتيح بعد أول تفعيل** |
| الخادم أُعيد تشغيله بمفاتيح توليد عشوائي | ثبّت `VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` في `.env` بقيم ثابتة (طالع `.env.example`) |

**ملاحظة تقنية:** إن ظهر خطأ `NO_SUBSCRIPTION` عند الاختبار فهذا يعني ببساطة أن هذا الجهاز لم يفعّل الإشعارات بعد — رسالة ودّية تظهر لك الآن بدل خطأ أحمر في الكونسول.

## 🚀 النشر على Railway (خطوة بخطوة)

1. **ارفع المشروع إلى GitHub**:
   ```bash
   git init && git add . && git commit -m "Rafiqi Nafsi v2.0 — MongoDB + WhatsApp"
   git branch -M main
   git remote add origin https://github.com/<حسابك>/rafiqi-nafsi.git
   git push -u origin main
   ```
   (ملف `.gitignore` يستبعد `node_modules` و`.next` و`.env`.)

2. **في Railway**: `New Project` → `Deploy from GitHub repo` → اختر المستودع.
   سيكتشف Railway تلقائياً مشروع Node (عبر `package.json`) ويشغّل:
   - Build: `npm install` + `npm run build`
   - Start: `npm start` (يستمع على `PORT` الذي يضبطه Railway)

3. **المتغيرات الإلزامية** في `Variables`:
   ```
   MONGODB_URI=mongodb+srv://<user>:<pass>@<cluster>.mongodb.net/rafiqi-nafsi
   ADMIN_PASSCODE=<كلمة-مرور-الإدارة>
   ```
   > أنشئ قاعدة مجانية على [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) (M0) — وفي `Network Access` اسمح بالاتصال من أي IP (`0.0.0.0/0`) أو من IPs Railway.

4. **متغيرات اختيارية**:

   | المتغير | الافتراضي | الغرض |
   |---|---|---|
   | `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` | توليد تلقائي + حفظ في `$DATA_DIR/vapid.json` | ثبّت إشعاراتك عبر إعادة النشر |
   | `VAPID_SUBJECT` | `mailto:stevenhacen@gmail.com` | بريد جهة الاتصال في VAPID |
   | `DATA_DIR` | `./data` | ثبّت Volume على `/data` واضبطه لحفظ مفاتيح VAPID المولدة |
   | `NEXT_PUBLIC_SOCKET_URL` | فارغ (نفس الخادم) | فقط إن فصلت خدمة المحادثة |

5. **دومين**: `Settings` → `Networking` → `Generate Domain` → ستحصل على `https://...up.railway.app`
   - HTTPS تلقائي → الإشعارات و PWA تعملان مباشرة.

6. **تحقق**: افتح `https://<نطاقك>/api` — يجب أن ترى `{"ok":true,"db":"connected",...}`.
   ثم أدخل أخصائيك الأول: `npm run db:add-counselor` من جهازك مع `MONGODB_URI` الخاص بـ Atlas، أو سجّله من واجهة المنصة ووثّقه من لوحة الإدارة.

### 💡 ملاحظة حول مفاتيح VAPID
بدون متغيرات بيئة ثابتة أو Volume، سيُعاد توليد المفاتيح عند كل إعادة نشر فتُلغى اشتراكات الإشعارات القديمة (يتعامل النظام معها تلقائياً بحذفها، لكن المستخدمين سيعيدون الاشتراك). الحل: ثبّت `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY` في Railway أو استخدم Volume.

## ▲ النشر على Vercel (وضع المزامنة)

منذ v2.3.2 تعمل المحادثة النصية على **كل المنصات** بفضل فصل طبقة النقل:

| المنصة | إرسال الرسائل | استلام الرسائل | مؤشر الحضور والكتابة |
|---|---|---|---|
| **Railway** (خادم موحّد) | REST `POST /api/messages` | فوري عبر Socket.io (جسر نفس العملية) | ✔ كامل |
| **Vercel** (serverless) | REST `POST /api/messages` | وضع مزامنة — استقصاء كل 4 ثوانٍ | ✖ (طبيعي في هذا الوضع) |

**لماذا؟** بنية Vercel serverless لا تدعم إبقاء اتصالات WebSocket حيّة، لذا كان `socket.io` يفشل هناك. الآن يرسل العميل رسائله عبر REST دائماً (مضمون في كل مكان)، ويحاول Socket.io كـ«أفضل جهد»، وعند تعذر الاتصال يتحول تلقائياً للاستقصاء — مع شريط أزرق يخبر المستخدم بلطف: «وضع المزامنة — قد تتأخر الرسائل ثوانٍ قليلة».

### خيار الترقية: محادثة فورية على Vercel أيضاً
وجّه عميل Socket.io في Vercel نحو خادم Railway (CORS مفتوح أصلاً):
1. في Vercel → `Settings` → `Environment Variables` أضف:
   ```
   NEXT_PUBLIC_SOCKET_URL=https://rafiqi-annafsi-production.up.railway.app
   ```
2. **أعد النشر** (المتغيرات المسبوقة بـ `NEXT_PUBLIC_` تُدمج وقت البناء).
3. النتيجة: إرسال REST (لا يفشل أبداً) + استلام فوري عبر غرف Socket.io على Railway.

> **إن كنت تستخدم `NEXT_PUBLIC_API_URL`** (وضع الوكيل من القسم السابق): طلبات REST ووضع المزامنة يعملان عبر الوكيل تلقائياً، لكن Vercel لا يمرّر ترقية WebSocket عبر الـ rewrites — لذا للمحادثة الفورية أضف `NEXT_PUBLIC_SOCKET_URL` كما أعلاه (العميل عندها يتصل بـ Railway مباشرة بدل الوكيل).

> ملاحظة: بروتوكول كشف الأزمة يعمل في الحالتين — عبر بث الخادم الموحّد على Railway، وعبر الكشف المحلي في العميل مع تسجيل الحالة في قاعدة البيانات (`crisis_logs` + `crisisFlag`).

## 🔐 ملاحظات أمان

- **`ADMIN_PASSCODE` إلزامي** — بدون لن تعمل لوحة الإدارة إطلاقاً. لا يوجد أي كلمة مرور افتراضية في الكود.
- بيانات المتضررين حساسة: احمِ `MONGODB_URI` (لا تشاركه أبداً) وفعّل النسخ الاحتياطي على Atlas.
- **لا يوجد أي بيانات تجريبية أو حسابات demo في الكود أو القاعدة** — كل ما تراه يأتي من بياناتك الحقيقية.
- ما يُتبادل عبر واتساب يخضع لسياسات واتساب وليس للمنصة — أطلع الأخصائيين على ذلك.
- الاستضافة عبر Railway توفر HTTPS تلقائياً (شرط عمل الإشعارات و PWA).
